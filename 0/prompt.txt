Bug 1:
In `Printf()`, the mutex is released before checking if `logger` is nil and calling `Init()`. This allows multiple concurrent goroutines to enter the unguarded `Init()` call. While `Init()` has its own mutex to prevent multiple initializations, the race condition creates a window where concurrent log calls could miss initialization or fail to synchronize properly. After `Close()`, the logger is reset to stderr, but `Init()` would detect `logger != nil` on subsequent calls and skip initialization entirely, potentially logging to the wrong destination.

Verify these issues exist and fix them:

Bug 1:
When a window is maximised for the first time without prior saved geometry, `MergeWindowGeometry` stores the full screen dimensions (e.g., 1920x1080 or larger on high-DPI displays) as the normal window bounds. On subsequent app launches, the window will open at this oversized dimension instead of the intended 1100×800 default. The fix requires detecting when maximised without prior bounds and either discarding the size or clamping to a reasonable maximum.

Bug 2:
A `setInterval` is established at module load time (line 399) that polls `SaveWindowState()` every 2 seconds while the document is visible. This interval is never cleared, causing indefinite polling to continue even if the window is closed or the app shuts down. While `SaveWindowState()` includes guards (`a.ctx == nil` check) that prevent errors, the unnecessary polling continues indefinitely, creating a resource leak and potential performance degradation.
